# 요구사항 문서 틀

`<...>`는 채울 곳이다. 아직 진행하지 않은 장은 제목만 두고, 진행 상황 표의 상태를 "전"으로 둔다.
대화에서 확인받은 표와 목록을 그대로 옮긴다.

````markdown
# <기능 이름> 요구사항

- 작성: <YYYY-MM-DD>
- 근거 문서
  - <문서 이름 버전> `<시트·절>`
  - <문서 이름 버전> `<시트·절>`

## 진행 상황

| 단계 | 하는 일 | 상태 |
|---|---|---|
| 1. 요구사항 정의 | 업무 흐름 그리기 → 요구사항 쓰기 → 빠진 것 되묻기 → 유스케이스 명세 → <확인할 사람> 확인 | <전 / 진행 중 / 끝. 답 기다리는 중 (1.5)> |
| 2. 구현 방법 | 요구사항마다 필요한 요소 뽑기 | <상태> |
| 3. 문제와 NFR | "이렇게만 하면 되나?"를 물어 숫자로 정하기 | <상태> |
| 4. 기존 설계·코드와 맞춰 보기 | <기존 설계 문서·코드>를 1~3과 비교해 다른 것만 고치기 | <상태> |
| 5. 검증 | <실제 환경>에서 <테스트셋·부하> 돌리기 | <상태> |

## 1. 요구사항 정의

### 1.1 업무 흐름

<기능>은 <사람>이 하던 일 중 <N>번을 대신한다.

| 순서 | <사람>이 하던 일 | 시스템에서 맡는 곳 |

(갈림길이 있으면)

```text

        └→ <단계>
```

### 1.2 요구사항

"나온 곳"은 그 요구사항이 어느 과정에서 나왔는지다. 흐름 = 1.1 업무 흐름, 되묻기 = 1.3, 구현 방법 = 2장을 쓰다가 발견.

| 번호 | 요구사항 | 나온 곳 | 근거 |
|---|---|---|---|
| 1 | <~해야 한다> | 흐름 <N> | <문서 `위치`> |
| 1-1 | <세부 조건> | 흐름 <N> | <문서 `위치`> |
| 2 | <~해야 한다> | 되묻기 | <문서 `위치`, 또는 "문서에 없음. 누가 언제 정함"> |
````
